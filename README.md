# IMU-Based Anomaly Detection for a UR3e Pick-and-Place Robot

An AI robotics laboratory project combining unsupervised anomaly
detection on inertial measurement unit (IMU) data with a browser-based
Cartesian gantry robot simulator.

## Project Overview

The project has two complementary components:

-   **IMU anomaly detection:** processes nine sensor channels and
    identifies unusual windows using k-nearest-neighbour (k-NN) novelty
    detection and Isolation Forest.
-   **Robot simulator:** visualises pick-and-place tasks, position,
    velocity, torque, payload-dependent dynamics, task scheduling, and
    controller behaviour.

The IMU recording is described as an unlabelled 1,000-row dataset. Since
real fault labels are unavailable, synthetic disturbances are used for
evaluation. The dataset is described as coming from a UR3e articulated
arm, while the HTML simulator models a Cartesian gantry. A validated
live connection between these components is not established by the
supplied materials.

## Key Features

-   Nine IMU channels: accelerometer, gyroscope, and magnetometer across
    X, Y, and Z.
-   Sliding windows of 25 samples with a stride of 5.
-   Mean and standard deviation features, producing 18 features per
    window.
-   Feature standardisation.
-   k-NN novelty score based on distance to the fifth-nearest normal
    window.
-   Isolation Forest baseline configured with 300 trees and 1%
    contamination.
-   Synthetic vibration bursts, spikes, and frozen sensor readings.
-   Blocked cross-validation with a gap to reduce leakage from
    overlapping windows.
-   Precision, recall, F1-score, and ROC-AUC evaluation.
-   Simulator graphs for position, velocity, and torque.
-   Task scheduling, perception refinement, payload-aware dynamics, and
    controller comparison.

## Methodology

1.  Load the IMU CSV and select the nine sensor channels.
2.  Create overlapping windows of 25 samples with a stride of 5.
3.  Calculate the mean and standard deviation for each channel.
4.  Standardise the 18-dimensional feature vectors using training data.
5.  Fit k-NN novelty detection on windows treated as normal.
6.  Fit Isolation Forest as a comparison model.
7.  Inject synthetic faults and retain their labels for evaluation.
8.  Calculate evaluation metrics and inspect channels associated with
    alarms.
9.  Export the trained model and result tables.

The project material specifies a k-NN alarm threshold of 1.5 times the
99th percentile of normal training scores.

## Running the Project

### IMU anomaly-detection notebook

1.  Open the project notebook in Jupyter Notebook or Google Colab.
2.  Make the source IMU CSV available at the path expected by the
    notebook.
3.  Install any required dependencies that are missing.
4.  Run the notebook cells in order, from preprocessing through
    evaluation.
5.  Review the generated plots and output files.

The presentation identifies `imu_pick_place.csv` as the input and
`anomaly_results.csv` and `evaluation_summary.csv` as generated outputs.
These results must be generated by running the notebook.

### Robot simulator

Open the supplied HTML simulator file in a modern browser. Configure
pick-and-place tasks, choose scheduling and controller options, and
inspect the position, velocity, torque, and task-result displays.

## Evaluation Metrics

-   **Precision:** proportion of flagged windows that correspond to
    injected-fault windows.
-   **Recall:** proportion of injected-fault windows successfully
    flagged.
-   **F1-score:** harmonic mean of precision and recall.
-   **ROC-AUC:** ability of anomaly scores to rank injected-fault
    windows above normal windows.

**Important:** Results from synthetic faults do not establish
performance on naturally occurring industrial failures. Report numerical
values only after running the notebook and checking its actual outputs.

## Limitations

-   The original IMU recording has no real fault labels.
-   Synthetic faults may not represent all real robot failures.
-   A single short recording may not represent all tasks, speeds, and
    payloads.
-   The UR3e dataset and Cartesian gantry simulator are different
    systems.
-   Quantitative results are unavailable until the notebook is run.
